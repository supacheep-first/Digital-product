# สายพาน (Pipeline) — จาก 0 ถึงเงินเข้าบัญชีจริง

> หลักการ: **แต่ละ stage ต้องผ่าน gate ก่อนไปต่อ** — ห้ามข้าม ห้ามลัด
> เหตุผลที่ต้องมี gate: กันไม่ให้ตัดสินใจด้วยความรู้สึกหรือความเบื่อ ทุกการข้าม stage ต้องมีเหตุผลเขียนไว้ใน `decisions/`

## Stage 0 — MAP: ทำแผนที่ตลาด 📍 *อยู่ตรงนี้*

**คำถามที่ต้องตอบ:** ตลาด digital product ทั้งใบหน้าตาเป็นยังไง **ฝั่งคนซื้อ**

| | |
|---|---|
| **Agent หลัก** | `market-cartographer` |
| **Agent สนับสนุน** | `fact-checker`, `red-team` |
| **Input** | ไม่มี — เริ่มจากศูนย์ |
| **Output** | `knowledge/01-market-landscape.md` (เขียนทับฉบับ 25 ก.ค. ที่เอียงฝั่งขาย) |
| **เวลาที่ควรใช้** | 1-2 session |

### Gate 0 → 1 (ต้องตอบได้ทุกข้อ)
- [ ] แบ่ง **buyer segment** หลักของตลาดได้กี่กลุ่ม แต่ละกลุ่มคือใคร
- [ ] แต่ละ segment **ซื้ออะไร ราคาเท่าไหร่ ซื้อจากที่ไหน ซื้อบ่อยแค่ไหน**
- [ ] **เงินก้อนใหญ่ที่สุดอยู่หมวดไหน** และหมวดไหนแข่งขันน้อยที่สุด (สองอันนี้มักไม่ใช่อันเดียวกัน)
- [ ] หมวดไหนกำลัง**โต** หมวดไหนกำลัง**ตาย** (พร้อมหลักฐาน ✅)
- [ ] เจ้าของโปรเจกต์อ่านแล้วบอกได้ว่า "อ๋อ ตลาดมันเป็นแบบนี้"

### เกณฑ์ล้มเหลวของ stage นี้
ถ้าผลลัพธ์ออกมาเอียงไปทางใดทางหนึ่ง (เช่น พูดถึงแต่สินค้าสาย dev) → **ถือว่าไม่ผ่าน** ต้องทำใหม่
`red-team` มีหน้าที่ตรวจข้อนี้โดยเฉพาะ

## Stage 1 — SCOUT: ล่าโอกาส

**คำถาม:** ในแผนที่นั้น มีจุดไหนบ้างที่ "มีคนเจ็บปวดและยอมจ่ายเงิน" แต่ยังไม่มีใครแก้ดี

| | |
|---|---|
| **Agent หลัก** | `niche-scout` |
| **สนับสนุน** | `competitor-analyst`, `fact-checker` |
| **Input** | market map จาก Stage 0 |
| **Output** | `research/YYYY-MM-DD-opportunity-longlist.md` |

### Gate 1 → 2
- [ ] มีโอกาสอย่างน้อย **20 รายการ** ที่มีสัญญาณ demand จริง (ไม่ใช่ไอเดียลอย ๆ)
- [ ] แต่ละรายการมี **หลักฐาน**: คนบ่นที่ไหน / มี search volume / มีคนจ่ายเงินให้ของคล้ายกันอยู่แล้ว
- [ ] แต่ละรายการระบุ **ใครคือคนจ่าย** และ **จ่ายเท่าไหร่**
- [ ] ต้องมีโอกาสที่ **ไม่ใช่สาย dev** อยู่ในลิสต์ด้วยอย่างน้อย 1/3 (กัน bias)

---

## Stage 2 — SCREEN: คัดกรอง

**คำถาม:** จาก 20-50 ตัว อันไหนเหมาะกับ *คนคนนี้* ที่สุด

| | |
|---|---|
| **Agent หลัก** | `decision-keeper` |
| **สนับสนุน** | `red-team`, `offer-architect` |
| **Output** | `decisions/00XX-shortlist.md` — ตารางคะแนน + เหตุผลที่ตัดตัวอื่นทิ้ง |

### เกณฑ์ให้คะแนน (แต่ละข้อ 1-5)
| เกณฑ์ | คำถาม |
|---|---|
| Demand จริง | มีคนจ่ายเงินให้เรื่องนี้อยู่แล้วหรือยัง |
| Unfair advantage | เจ้าของโปรเจกต์รู้เรื่องนี้ดีกว่าคนทั่วไปไหม |
| ทน AI ได้ไหม | ถ้า Claude/ChatGPT generate ได้ใน 1 ชม. = ตัดทิ้ง |
| ข้อจำกัดไทย | ขาย/รับเงิน/ทำ support จากไทยได้ไหม |
| ความ passive | หลังขายแล้วต้องดูแลแค่ไหน |
| เวลาถึงเงินก้อนแรก | กี่สัปดาห์ |
| ต้นทุนถ้าล้มเหลว | เสียเวลา/เงินเท่าไหร่ถ้าไม่เวิร์ก |

### Gate 2 → 3
- [ ] เหลือ **3-5 ตัวเลือก** พร้อมคะแนนและเหตุผล
- [ ] `red-team` ถล่มทุกตัวแล้วและยังมีตัวที่รอด
- [ ] **เจ้าของโปรเจกต์เป็นคนเลือก** ไม่ใช่ agent เลือกให้

---

## Stage 3 — VALIDATE: พิสูจน์ว่ามีคนจ่าย

**คำถาม:** คนแปลกหน้ายอมควักเงินจริงไหม — ก่อนที่เราจะลงแรงสร้าง

| | |
|---|---|
| **Agent หลัก** | `demand-validator` |
| **สนับสนุน** | `copywriter`, `offer-architect` |
| **Output** | `research/YYYY-MM-DD-validation-<slug>.md` |

**วิธีทดสอบที่ยอมรับได้** (เรียงจากหลักฐานแข็งสุด):
1. 💰 **มีคนจ่ายเงินจริงก่อนของเสร็จ** (pre-sell / deposit) ← หลักฐานแข็งที่สุด
2. 📧 คนใส่อีเมลลง waitlist หลังเห็นราคา
3. 💬 คนตอบ DM/สัมภาษณ์ว่า "จ่ายเท่าไหร่" แล้วตอบเป็นตัวเลข
4. 👀 landing page มี traffic แล้ววัด conversion

**ไม่นับเป็นหลักฐาน:** เพื่อนบอกว่าดี / ยอด like / คนบอกว่า "น่าสนใจ"

### Gate 3 → 4
- [ ] มีหลักฐานระดับ 1 หรือ 2 จาก**คนที่ไม่รู้จักเจ้าของโปรเจกต์**
- [ ] รู้ราคาที่คนยอมจ่ายแล้ว (ไม่ใช่ราคาที่เราอยากขาย)
- [ ] คำนวณแล้วว่า ถ้าขายได้ N ชิ้น จะได้เงินเข้ากระเป๋าจริงเท่าไหร่หลังหักค่าธรรมเนียม

### 🔴 เกณฑ์ kill
ทดสอบ 2 สัปดาห์แล้วไม่มีสัญญาณระดับ 1-2 เลย → **กลับ Stage 2 เลือกตัวถัดไป** ไม่ต้องเสียดาย

---

## Stage 4 — BUILD: สร้าง v1

| | |
|---|---|
| **ผู้ทำ** | เจ้าของโปรเจกต์ + Claude (ไม่ต้องใช้ agent พิเศษ) |
| **สนับสนุน** | `monetization-ops` (ต่อระบบรับเงิน), `red-team` (กันการทำเกิน) |

**กฎ:** ตัดฟีเจอร์จนเหลือ**สิ่งเดียว**ที่แก้ปัญหาได้ ทุกอย่างที่เพิ่มมาต้องตอบได้ว่า "ถ้าไม่มีอันนี้ ลูกค้าจะไม่จ่ายเหรอ"

### Gate 4 → 5
- [ ] คนแปลกหน้าเข้ามาแล้ว**ซื้อจนจบได้ด้วยตัวเอง** (จ่ายเงิน → ได้ของ → ใช้งานได้)
- [ ] ทดสอบซื้อจริงด้วยบัตรจริงอย่างน้อย 1 ครั้ง
- [ ] มีวิธีติดต่อกลับหาลูกค้า (email list)

---

## Stage 5 — LAUNCH & DISTRIBUTE

| | |
|---|---|
| **Agent หลัก** | `launch-manager` |
| **สนับสนุน** | `copywriter`, `seo-strategist`, `audience-builder`, `media-buyer` |

**หมายเหตุ:** `audience-builder` ควรเริ่มทำงานตั้งแต่ **Stage 1** ไม่ใช่มาเริ่มตรงนี้ — audience ใช้เวลาสะสม

### Gate 5 → 6
- [ ] Launch ครบ 4 ช่องในวันเดียว
- [ ] มี **traffic engine** ที่ทำงานต่อเนื่องได้อย่างน้อย 1 ตัว (SEO / community / social)
- [ ] มียอดขายจาก **คนที่ไม่รู้จักเจ้าของโปรเจกต์**

---

## Stage 6 — OPERATE: รับเงินและดูแล

| | |
|---|---|
| **Agent หลัก** | `monetization-ops` |
| **สนับสนุน** | `support-retention`, `funnel-analyst` |

### Gate 6 → 7
- [ ] เงินเข้าบัญชีจริง (ไม่ใช่แค่ยอดในแดชบอร์ด)
- [ ] รู้ตัวเลข: CAC, conversion rate, refund rate, (ถ้า subscription: churn)
- [ ] มีระบบ support ที่ไม่กินเวลาเกิน N ชม./สัปดาห์
- [ ] คุยกับนักบัญชีเรื่องภาษีแล้ว

---

## Stage 7 — DECIDE: kill หรือ scale

| | |
|---|---|
| **Agent หลัก** | `decision-keeper` |
| **สนับสนุน** | `red-team`, `funnel-analyst` |

**คำถามเดียว:** มีรายได้จาก organic ที่โตต่อเนื่องโดยไม่ต้องผลักทุกวันไหม

| ผลลัพธ์ | ทำอะไรต่อ |
|---|---|
| โตต่อเนื่อง | **Scale** — เพิ่ม traffic engine, ขึ้นราคา, ขยาย offer |
| นิ่ง แต่มีเงินเข้า | **Milk** — ปล่อยให้อยู่ แล้วเอาเวลาไปเริ่มตัวใหม่ที่ Stage 1 |
| ไม่มีอะไรเลย | **Kill** — เก็บ audience + บทเรียนไว้ กลับ Stage 1 |

**ทุกครั้งที่ตัดสินใจ ต้องเขียนลง `decisions/` พร้อมเหตุผล** — เพื่อให้ 6 เดือนข้างหน้ายังรู้ว่าทำไมถึงเลือกแบบนั้น

---

## กฎการเดินสายพาน

1. **ห้ามข้าม stage** — ถ้าจะข้าม ต้องเขียนเหตุผลลง `decisions/` ก่อน
2. **ถอยหลังได้ ไม่ใช่ความล้มเหลว** — Stage 3 ไม่ผ่าน แล้วกลับไป Stage 2 คือระบบทำงานถูกต้อง
3. **`red-team` เรียกได้ทุกเมื่อ** โดยเฉพาะตอนที่รู้สึกมั่นใจมาก ๆ
4. **อัปเดต [STATUS.md](STATUS.md) ทุกครั้งที่ผ่าน gate**
